algodtop Docs

algodtop

Monitoring for algod nodes. A terminal UI in the style of top, a daemon that keeps history, and a web UI. It is one binary, with no database or other service to run.

go install algod.top@latest            # a command named algod.top
go install algod.top/algodtop@latest   # the same program, named algodtop

Use either one. The docs call it algodtop. It needs Go 1.27 or later and runs on Linux, macOS and Windows. To try it without installing, run go run algod.top@latest. Then read the quick start.

One fleet, three ways to look at it

The terminal UI and the web UI read the same daemon. Without a daemon, the terminal UI polls algod directly and shows live values.

What it watches

It collects everything algod reports, keeps it for as long as you choose, and turns the parts that matter into health you can read.

Rounds and sync

Round time from the local arrival of every round, sync lag and catchup.

Peers

Connections by network and direction, churn and disconnect reasons, and per-peer traffic where algod reports it.

Participation

Key validity, last votes and proposals, online status and incentive eligibility, with alerts before a key expires.

The machine

CPU, memory, disk use with the days until it fills, and the clock offset.

The log

Error and warning lines in node.log, grouped into templates and counted per minute.

Many hosts

Local data directories, REST URLs, SSH with nothing installed, and agents that buffer data while the hub is away.

Start in a minute

algodtop                    # find the nodes on this machine and show them live
algodtop daemon --discover  # keep their history and serve the web UI on 127.0.0.1:8090
algodtop service            # start the daemon at login or boot

The documentation covers configuration, remote hosts, alerts and storage.
